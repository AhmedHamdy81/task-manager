Overview

Access Control is the studio’s permission manager. Nothing is allowed unless it is granted. Use this area to decide which roles and job titles can view or change each part of the app, then add per-person exceptions when needed.

Open it from Admin → Access Control. The left sidebar switches between the six working screens plus this Help page.

How access is decided

When someone opens a page or tries an action, the app checks grants in this order:

  1. User override — an explicit Allow or Deny for that person on that page + action. This wins.
  2. Job title — grants attached to the person’s directory job title.
  3. Role — grants attached to their account role (Administrator, Producer, Editor, and so on).
  4. Default deny — if nothing granted the action, it is blocked.

Administrators who can open this screen have manage_permissions. Guests never appear in the role list.

Pages

Pages are the app modules you can protect — Dashboard, Projects, Machine Room, Booking, and so on. Each card shows:

Name
Human label used in this UI and in matrices.
Module badge
Grouping (core, admin, machine room, and others) used to organize Role and Job title screens.
Key
Stable id (for example projects) stored in the database.
Route
URL pattern this page covers.
Inactive
Shown if the page is registered but turned off in the catalog.

Use the search box to filter by name, key, or module. Pages themselves are not edited here; they are seeded with the app. You grant actions on these pages in the Role and Job title screens.

Actions

Actions are the verbs you can grant on a page: View, Create, Edit, Delete, Upload, Approve, and more specialized ones (Machine Room copy, VFX shots, notification audit, and so on).

The matrix screens only show the common verbs used across most modules (view, create, edit, delete, upload, assign, export, and a few admin/machine-room verbs). The Actions catalog lists every verb in the system so you know what a grant means.

Role permissions

Pick a role, then turn action chips on or off per page. Modules are grouped in expandable sections. A chip that is on means that role may perform that action on that page.

Role
Account role (Administrator, Producer, Editor, Colorist, Machine Room, …). Guest is excluded.
Filter modules
Narrows the matrix by page name, key, or module.
Chips
Click to toggle. Changes stay local until you press Save changes.

Unsaved changes are flagged in the header. Leaving the Role or Job title screens without saving discards pending toggles.

Job title permissions

Same matrix as roles, but keyed to a directory job title (for example Offline Editor). Use this when two people share a role but should not share the same access — or when a title should carry extra rights regardless of role.

Job title grants stack with role grants. A person gets an action if either their role or their job title allows it, unless a user override says otherwise.

User overrides

Overrides are exceptions for one person. They beat both role and job title.

User
Directory person to target.
Page
Which module the exception applies to.
Action
Which verb to Allow or Deny.
Allow
Allow grants the action; Deny blocks it even if the role would allow it.
Note
Optional reason stored with the override (useful for audits).

Add override applies immediately. Remove deletes that exception. There is no extra Save on this screen.

Permission preview

Preview shows the effective access for one person after role, job title, and overrides are combined. Use it to confirm a change before telling the crew it is live.

Choose a user and press Refresh preview (or change the user). Each page card lists whether they can view it and which actions they currently have. Hover a badge to see whether the grant came from role, job title, or override.

Saving changes

Save changes appears only on Role permissions and Job title permissions. Toggle chips first; the header shows Unsaved changes until you save. Overrides and preview do not use that button.

After a successful save, people may need to refresh or sign in again for menus and API checks to pick up the new grants.

Tips

  • Start from Preview when someone reports “I can’t see X” — it shows the real combined result.
  • Grant view before other verbs; most screens require view to open at all.
  • Prefer job titles for craft-specific access and roles for broad studio bands. Use overrides sparingly.
  • A Deny override is the cleanest way to block one person without shrinking a whole role.
